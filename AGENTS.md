# Project conventions

Dauerbot is an open-source project for a global audience. English is the project language. Use English for repository descriptions, README and other documentation, code comments, default UI and CLI text, release notes, commit messages, issue titles, and pull request titles and descriptions. This project-specific rule overrides the parent's default of Chinese commits and PRs. Desktop localization resources may provide English and Simplified Chinese UI, with a persistent user language preference. Keep English as the default and repository language. Preserve user content, proper names, and multilingual test fixtures in their original language. Do not rewrite published Git history to translate old commits.

The user-facing client is the native Rust/GPUI macOS application in `desktop/`. Do not add a web interface, WebView, Svelte, or a JavaScript build toolchain. Desktop, CLI, and MCP share the independent Rust daemon's API. Network requests and file access checks must never block GPUI's main thread.

Check macOS access against paths that the user explicitly selects. Do not scan private databases, call private TCC APIs, or treat one accessible file as proof of Full Disk Access. Explain that the desktop, daemon, HERDR, and Agent can have different permissions.

Product execution uses legacy `herdr` 0.9.5, not the incompatible `hc`/herdr-core backend. Keep runtime control behind the legacy backend module; desktop observes or controls the same execution through its native terminal stream. Do not change a user's real HERDR configuration or terminate their terminals. Legacy HERDR tests must use a private `XDG_CONFIG_HOME`, named `HERDR_SESSION`, and a short temporary path. Development delegation through herdr-subagents continues to use `hc` as directed by that skill, separately from product execution. Keep the default bundle ID and data directory compatible across renames and upgrades; clearly label windows that use independent data directories.

Keep credentials out of Git, logs, and screenshots. Live Feishu tests must name the intended bot and chat and must not compete with an existing bot's event listener. Message submission does not prove completion; preserve `uncertain` results rather than retrying automatically.

The owner's MacBook Pro and Mac mini have completed the pre-refactor transition. Do not retain or reintroduce an hc/Core adapter, dual-backend support, Core execution archives, or migration notices. Support fresh stores and normal schema upgrades from the migrated installation onward. The selected `herdr` 0.9.5 backend remains the product runtime. Ordinary daemon protocol checks, execution identity checks and storage version checks remain part of current operation.

Remove obsolete code and dependencies with the feature they served. Add tests only for meaningful behavioral regressions. Run the relevant Rust tests and clippy for code changes; use the isolated protocol smoke test when changing daemon, CLI, MCP, or message handling.

Package the native app with `scripts/build-desktop.sh`; it must build without Node.js or pnpm. Local ad-hoc signatures are for development, not proof of Developer ID signing, notarization, or Gatekeeper acceptance. Public macOS releases must use Developer ID Application signing, Apple notarization, a stapled ticket, and Gatekeeper acceptance before packaging. Publish version tags only from `main`. Never overwrite a public release or silently change the update signing key.

Keep GitHub Actions usage low. Routine pushes and pull requests must not start native builds. Run the relevant build, tests, and clippy locally; cloud native checks are manual only. Releases require a locally built and tested staged package. Validate the tag and staging metadata on Ubuntu before allocating macOS for signing and notarization. Never add an automatic cloud compilation fallback.

The built-in project manager is an internal restricted Rust actor above the existing native CLI worker. All projects use Manager/Worker mode. Configure the shared manager provider explicitly. Preserve queued input when the provider is unavailable and never fall back to standalone native execution. Manager API credentials are separate from native CLI login/settings; never scrape or copy those credentials. Keep its tool registry finite and host-authorized, without shell, arbitrary process execution, generic HTTP or arbitrary MCP access. Manager tools are internal and do not expand the three-tool native project MCP interface. The daemon owns mode transitions, input ownership, checkpoints and uncertain external effects; a model response must not override pause, Stop, takeover or native generation authority. Test provider behavior with local fixtures and isolated stores, never real accounts by default.

The built-in Manager instructions and its proposal-generation prompt use Simplified Chinese by maintainer direction. Keep default user-visible controls and descriptions in English, and generate proposal content in the user’s language.

Before merging a source pull request, inspect its full diff for scope and sensitive data, confirm every required check passes, and address every review comment with a fix or an explicit reason. Resolve review threads only after that response is recorded. Use the installed `codex-babysit-pr` skill and invoke its bundled wait script by its absolute path (`$HOME/.codex/skills/codex-babysit-pr/wait-codex-review.sh`); follow its result and repeat after fixes until review and checks are clear. Verify that automated review completion applies to the current PR head; script warnings, API failures and stale approval reactions are not approval. Do not treat a successful merge command as review completion.
